# 스키마 변경 절차

1. **변경안 작성**: Drizzle 스키마 파일 수정 → `drizzle-kit generate`로 마이그레이션 SQL 생성. DB에 직접 DDL을 치지 않는다.
2. **독립 검토**: schema-reviewer 에이전트에 마이그레이션 diff를 넘겨 판정을 받는다. 반려면 수정 후 재검토.
3. **브랜치 리허설**: Neon 브랜치 생성 → 브랜치에 마이그레이션 적용 → 대표 쿼리(갤러리 조인, 클릭 집계) 실행으로 회귀 확인. 데이터 이동이 있는 변경은 행 수 before/after 비교.
4. **main 적용**: 리허설 통과 후 main에 적용. 마이그레이션 파일 커밋 (스키마 이력은 깃에만 존재해야 한다).
5. **사후 확인**: 다음 야간 스냅샷이 새 스키마로 정상 생성되는지 확인. SPEC.md §2의 스키마 서술이 실제와 어긋나면 SPEC.md 갱신.
6. **브랜치 정리**: 리허설 브랜치 삭제.

## 금지

- 불변 ID 컬럼(videos.id, video_no, templates.slug, short_links.slug, books.isbn)을 건드리는 변경은 어떤 리허설로도 정당화되지 않는다 — 제안 자체를 반려하라.
- 검토(2)와 리허설(3)을 건너뛴 main 적용 금지.
